# Output formats

**Status**: building

## User problem
One story has several readers with different jobs: the player, the proofreader, the writer
checking what their pull request changed, the writer hunting for the exact name of a passage to
link to, and the writer tracking word counts. A single view serves none of them well, and a view
that shows stale or made-up status is worse than no view.

## User stories
- As a player, I want to play the story in a browser.
- As a proofreader, I want every passage as plain text on one page.
- As a writer, I want to see the story as a map of passages and links.
- As a writer, I want every route through the story with what my pull request changed, so that
  I can read the routes my passage sits on.
- As a writer, I want a list of every passage with its file, line and links, so that I can link
  to a passage without guessing its name.
- As a writer, I want word counts per passage and per file, so that I can track my progress.
- As a player, I want a short id at each ending, so that I can tell others which route I took.

## Behavior
Every build writes these pages to `dist/`; the landing page links to all of them, in the pull
request preview and on GitHub Pages.

| Page | File | What it shows |
|---|---|---|
| Landing | `index.html` | The story title and a link to every page below |
| Play | `play.html` | The story in Harlowe, starting at the StoryData start passage |
| Proofread | `proofread.html` | Every passage as text on one page (Paperthin) |
| Graph | `graph.html` | Passages and links as a diagram (DotGraph) |
| All paths | `allpaths.html` | Every route from the start to an ending |
| Metrics | `metrics.html` | Word counts and distributions |
| Passages | `passages.html` | The passage index |
| Story Bible | `story-bible.html` | See [story-bible](story-bible.md) |

**All paths.** A route runs from the start passage to a passage with no working links. Each
route shows its passages in order, the files they come from, when those files were first and last
committed, and a category relative to the pull request's merge base (or `HEAD` on `main`):
*new* (the route did not exist and has a new passage or new prose), *modified* (the route existed
and something on it changed, or it is new only because links changed), or *unchanged*. Buttons
filter by created or modified in the last day or week. Each route also has plain-text files:
`allpaths-clean/path-<id>.txt` (what a reader reads), plus metadata and raw-markup variants used
by the AI editors.

**Metrics.** Counts only prose a reader sees: link text counts, markup and macros do not, and
footer, header, script and stylesheet passages are left out. Shows totals, per-file counts,
min/mean/median/max per file, the longest passages, and a passage-length distribution.

**Passages.** One row per passage in file order: name, `file:line`, tags, the writer's initials
and date from the file name, the day from the `Day <N>` passage, word count, links out, links
in, and a filter box.

**Path IDs.** At each ending, the play page shows `Path ID: <8 hex digits>` and the route's
passage names. The id links to that route's clean text file. The id is derived from the route's
passage names and text, so it changes when any passage on the route changes. The lookup behind it
(`src/PathIdLookup.twee`) is generated by every build and is not committed.

## Acceptance criteria
- AC-output-formats-1: Every build produces `play.html` (Harlowe), `proofread.html` (Paperthin) and `graph.html` (DotGraph) from `src/`, and a build that cannot produce one of them fails. (verify: workflow)
- AC-output-formats-2: Every link on the landing page opens an existing page, in the pull request preview and on GitHub Pages. (verify: workflow)
- AC-output-formats-3: The landing page shows the title from `StoryTitle`.
- AC-output-formats-4: The All Paths page lists one entry per route from the start passage to an ending, in link order, with the route's passage names, files, created and modified dates, and category.
- AC-output-formats-5: A route that existed at the base with any passage changed is *modified*; a new route containing a new passage or changed prose is *new*; a new route whose only changes are links is *modified*; every other route is *unchanged*.
- AC-output-formats-6: Categories compare against the pull request's merge base when one is given, otherwise `HEAD`; when the base has no story, every route is *new*.
- AC-output-formats-7: The All Paths page shows no validation status, and the build writes no validation-status file.
- AC-output-formats-8: Each route's clean text file contains only the passage text a reader sees, with links shown as their display text and links not taken shown as `[unselected]`.
- AC-output-formats-9: A link to a missing passage is not followed and is not a route of its own; a passage whose only links are broken ends its route; the build log names each broken link once. A cycle is cut where it repeats and the route still reaches an ending.
- AC-output-formats-10: The created/modified-in-the-last-day/week buttons on the All Paths page hide routes outside the chosen window and combine with AND. (verify: manual)
- AC-output-formats-11: Passage text on the All Paths page and passage names on the Passages page are HTML-escaped, so markup in prose or names shows as text.
- AC-output-formats-12: Metrics count link display text as words and leave out macros, HTML tags, and passages tagged `footer`, `header`, `script` or `stylesheet`, and the StoryData and StoryTitle passages.
- AC-output-formats-13: The Metrics page shows total words, passage count, file count, words and passages per file, min/mean/median/max words per file, the longest passages, and a five-bucket passage-length distribution, under the title from `StoryTitle`.
- AC-output-formats-14: `nanoif build metrics --include <prefix>` and `--exclude <prefix>` count only, or skip, files whose names start with the prefix.
- AC-output-formats-15: The Passages page has one row per passage sorted by file then line, with `file:line`, tags, initials and date from the file name, the day from the `Day <N>` passage, word count, links out, and links in.
- AC-output-formats-16: The Passages page shows "<N> passages in <M> files" with the build time, has a filter box, and marks passages that have no source file in `src/`.
- AC-output-formats-17: A route's path id is 8 hex digits computed from its passage names and text, and it changes when any passage on the route changes.
- AC-output-formats-18: The id shown for a route in the play page's lookup, on the All Paths page, and in the name of its clean text file is the same id.
- AC-output-formats-19: Every build regenerates the path-id lookup as a single script passage that covers every route of the current story.
- AC-output-formats-20: At an ending in `play.html`, the player sees `Path ID: <id>` linking to that route's clean text, and the route's passage names; passages with links show no id. (verify: manual)

## Edge cases
- **Empty story** (the `Start` stub only): every page renders; All Paths shows one route; Metrics
  shows one passage; the Story Bible shows its placeholder. No landing link breaks.
- **Broken link on a route**: the route ends early at that passage; the structure check reports the
  error ([structure-check](structure-check.md)).
- **File not yet committed**: it adds no dates; a route whose files are all uncommitted shows
  "Unknown" for created and modified.
- **A reader reaches an ending by a route the lookup does not know** (the story changed since the
  page was built): no path id is shown rather than a wrong one.
- **Very large stories**: All Paths grows with the number of routes; its path text is collapsed by
  default and expands per route.

## Soft goals
- A writer finds any passage name in the Passages page within a few seconds.
- Players use path ids when they talk about the story.
