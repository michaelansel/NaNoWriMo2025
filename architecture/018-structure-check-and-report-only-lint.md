# ADR-018: Structure check and passage index replace resource tracking; the linter only reports

## Status

Status: Accepted

## Context

Two automations used to write to writers' PR branches: a resource-tracking step that regenerated a `Resource-Passage Names` file from the source, and a Twee linter run with `--fix` that rewrote formatting (including smart quotes) and committed the result. Together they produced dozens of bot commits per writer, conflicts on the next edit, and prose the writer had not typed. The one defect worth catching in practice was a broken link, which needs no model.

## Decision

Deterministic checks report; nothing rewrites or commits to a PR branch (ADR-014).

- **`nanoif check structure <src>`** (`nanoif.check.structure`) reads `src/` and `story-overrides.txt` and reports findings with level, code, file, line and passage (`--format text|json|github`; JSON schema `structure_findings`).
  - Errors: broken links (every link form the one link parser knows), duplicate passage names, missing or invalid `StoryData`, unreadable files, `story-overrides.txt` syntax errors.
  - Warnings: orphans (unreachable from the `StoryData` start), file names that are neither `<INITIALS>-<YYYYMMDD>.twee` nor an infrastructure file, prose files without a `:: Day <N> <INITIALS>` passage, unknown `storyStyle` keys.
  - Info: reachable dead ends not tagged `ending`.
  - It exits 1 on any error. In the PR `build` job its findings become annotations on the `.twee` lines and the `Structure` check run: failure on errors, neutral on warnings, success otherwise. The build and preview still complete.
- **`nanoif lint`** (`nanoif.twee.lint`) reports formatting rules only. `fix_file` exists for tests and is not reachable from the CLI; the smart-quotes rule is gone. In CI its findings are warning annotations that never fail the build; that is done with an explicit report-only exit mode, not `continue-on-error`.
- **`dist/passages.html`** (`nanoif.formats.passages`) replaces `Resource-Passage Names`: every passage with file:line, writer and day inferred from the file name, links in and out, and word count. It is built from `story_graph.json` on every build and never committed.
- `src/PathIdLookup.twee` is generated by `nanoif build core` for the playable build and is git-ignored.
- Writers' formatting and naming are advice; only errors that break the story or its tooling fail a check.

## Consequences

### Positive

- A broken link is reported with its file and line on the PR within minutes, with no model and no commit.
- Writers' branches contain only writers' commits; nothing conflicts with their next edit.
- The passage index is always current because it is rebuilt, not maintained.

### Negative

- Formatting drift is only advised; if nobody acts on it, the source stays untidy.
- Whether `Structure` blocks merge is a branch-protection policy, not something this design enforces.

## Alternatives Considered

1. **Auto-fix and commit**: the harm this ADR removes.
2. **Suggested changes as review comments**: still noise on every PR, and a web-UI writer would apply them blindly.
3. **Keep a committed passage list, regenerated on main only**: a file that is stale on every PR branch.
